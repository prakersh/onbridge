# Tools

OnBridge exposes 40 tools over MCP. Your agent chooses among them on its own; this page is for people who want to know what they do, or who are writing prompts and agents around them.

| Group | Tools |
|---|---|
| Observe | `snapshot` · `find` · `extract_text` · `list_actions` · `get_text` · `get_url` · `screenshot` · `highlight` |
| Interact | `click` · `click_by_text` · `type` · `fill_form` · `select` · `hover` · `scroll` · `press_key` · `drag` · `upload` · `dismiss_modal` |
| Navigate | `navigate` · `back` · `forward` · `reload` · `wait` |
| Tabs | `list_tabs` · `switch_tab` · `new_tab` · `close_tab` |
| Advanced | `evaluate` · `dom_query` · `get_cookies` · `set_cookie` · `console_logs` · `network_requests` · `network_request_body` · `download_file` · `list_downloads` · `activity_log` |
| Session | `ask_user` · `bridge_status` |

Which of these ask for your approval is covered in [How OnBridge keeps you in control](security.md#what-the-agent-may-do).

## Behaviour worth knowing

- **A performed action is never reported as a failure.** `click`, `click_by_text`, `scroll`, `dismiss_modal` and `navigate` return `{ ok, navigated, url, title, snapshot? }`. If the action ran but the page could not be captured afterwards — the usual case when a click navigates — the call still succeeds, says why there is no snapshot, and gives you the new URL. Never retry a click on an error: it may already have happened.
- **Reading a page cheaply.** `extract_text` is the cheap way to *read* (tables come back as markdown); `snapshot` is for *acting*. `find` is cheaper still when you know what you are looking for. On a heavy page the snapshot is most of the cost of a `navigate`, so `navigate(url, snapshot: false)` followed by `find` or `extract_text` is the cheap pattern; `compact` and `depth` work there too.
- **Following a link without clicking it.** `find` and `dom_query` report absolute hrefs, and `dom_query` has an `attr` action. Reading a result's destination and navigating to it directly avoids the most failure-prone thing the bridge does.
- **A second action on the same page returns only what changed.** Every whole page an agent is sent is numbered ("This is page view 7."). When a later `click`, `scroll` or similar stays on that page, the reply shows only the changes since that view: `+` added lines, `-` removed lines, unmarked lines that show where each change sits, and `…` for skipped unchanged lines. Changes are always relative to the last whole page, never to another change-only reply, and the view plus the changes is exactly the page's current text. The whole page is sent instead after a navigation, and whenever the changes would not be clearly smaller. `snapshot` always returns the whole page.
- **Snapshots leave out lines that carry nothing:** separator glyphs such as `-` and `|` between links, and a plain `[group]` wrapper with a single child (the child takes its place). No ref, no text and no grouping of siblings is lost.
- **Long text comes in parts.** `extract_text` returns up to 20,000 characters (`maxChars`) and, when it stops early, says so outside the page content: which characters it returned, of how many, and the `offset` to pass to read the next part. It ends a part on a line break where one is near.
- **Every page tool takes a `tabId`** (from `list_tabs` or `new_tab`), so several tabs can be worked side by side without `switch_tab`: compare four shops by reading each tab in turn. The tab has to be inside the control the user granted, and refs belong to the tab they came from.
- **Refs keep their numbers across snapshots** for as long as their element exists, and a ref whose element is gone, or that was issued for another tab or an earlier document, is refused with a `[stale-ref]` error that names the ref and says to take a fresh snapshot. Nothing is done with a stale ref: it never resolves to whichever element has that number now. With an extension from before this, which renumbers refs on every capture, the server refuses any ref issued before the latest capture instead, and says the extension should be updated.
- **`type` and `fill_form` reach a field differently.** `type` clicks the field and sends real keystrokes, which is what React, Vue and autocomplete fields expect; it reports what the field holds afterwards, and if the keystrokes left it empty it sets the value directly once and says so. `fill_form` sets each value directly and fires `input` and `change`, and names any ref it could not find. If one does not take on a site, use the other.
- **Waiting for a page.** `wait` with no condition waits for the page to finish loading and its content to stop changing; with `text`, `textGone` or `selector` it waits for that, and a timeout comes back as a typed `[wait-timeout]`, not as page text. `navigate`, `click` and `click_by_text` take the same conditions as `waitFor` and capture the page once the condition holds. `click_by_text` keeps looking for its text for up to `timeoutMs` (default 5 seconds) before failing, so a page still filling in does not need a separate wait.
- **`dom_query` reads several values per match in one call.** With `action: "list"`, `fields` maps a name to where to read it from each match: a sub-selector for a descendant's text (`"h2"`), `"@attr"` for an attribute of the match itself (`"@data-asin"`), or `"sub@attr"` for a descendant's attribute (`"a@href"`). `limit` raises the row count to 100. With an older extension the server reads the match's own attributes separately and says which fields need an update.
- **A disconnect says why.** When the browser hangs up on purpose (Control Mode turned off, idle revoke, a pairing forgotten, the user disconnecting one agent) the next tool call says so and does not wait for a reconnect. A connection that was simply lost is described as such, with how long ago, and the call waits for the extension to come back, which it does on its own; a grant it held is restored, including across a restart of the extension's background worker. A command that was in flight when the browser went is reported as "may or may not have run".
- **Personal data can be blanked out of page text**: phone numbers, email addresses and card numbers, when the user turns it on in the panel or the server is started with `ONBRIDGE_REDACT`. It is applied where page text is fenced, so it covers every tool. Postal addresses are not attempted: nothing recognises them reliably. Order and reference numbers shaped like phone numbers are hidden too, which is the trade the user makes by turning it on.
- `extract_text` distinguishes "no such ref", "this element is genuinely empty" and the text itself. It never answers a scoped read with a bare empty string.
- `list_actions` answers "what can I do here?" for a fraction of a snapshot.
- Shadow DOM and iframes are captured. Refs are frame-qualified automatically, and clicks and typing inside an iframe are real trusted input — including cross-origin frames, which run in their own process.
- A lost ref is re-resolved from a recorded locator instead of failing outright, when the element has a name, placeholder or id to find it by again. An unnamed element is refused rather than guessed at.
- A page caught between documents returns a typed, retryable error rather than Chrome's raw *"Could not establish connection"*, so a retry is distinguishable from a refusal.
- `navigate` tells you when it landed on a different origin than you asked for.
- `bridge_status` answers even before the agent has been given control, and reports the connection code the user should look for in the panel.
- `get_url` reads Chrome's tab list, so it works on `chrome://` pages and the New Tab page, where tools that read the page itself cannot run.
- A command the installed extension is too old to run is refused up front, with a message saying the extension needs updating, rather than failing obscurely.
